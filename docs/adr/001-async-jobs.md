# ADR-001: 异步任务架构

## 状态

已接受（2026-10）

## 背景

step-5 推理模型生成一份行程需要 3-5 分钟（跨境 8 分钟+）。同步 HTTP 请求无法承受这个延迟。

## 决策

POST /api/plan 立即返回 jobId（202），生成在服务端后台进行，前端每 3 秒轮询 /api/plan/status。

## 理由

- 同步等待会撞 Node fetch 的 undici headersTimeout（默认 300s）
- 用户可以看到进度（已等待时间、已生成天数），不是干等
- 任务状态经 Store 层持久化，失败自动归还配额

## 后果

- 必须用常驻 Node 服务（不能用纯 serverless，函数响应后会被冻结）
- 需要任务心跳 + 陈旧自愈（服务重启后僵尸任务检测）
- 需要流式总时长兜底（上游挂住时不产生永远 running 的任务）
