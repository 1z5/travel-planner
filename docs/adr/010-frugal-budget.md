# ADR-010: 预算下限 0（穷游模式）

## 状态

已接受（2026-10-24）

## 背景

线上实测反馈：「个人预算有 ≥500 的限制，有些人就想穷游 Citywalk」。原实现
`budget: min(500)`，且预算目标写死「总花费应落在 80%-100% 预算之间」。

放开下限不只是改一个数字——低预算会在管线上**连环出错**：

1. 预算 0 时该指令算出「应落在 1-0 元之间」的自相矛盾区间，模型只能瞎编；
2. 体检把任何花费都判「超支」，且 `grandTotal / budget` 输出 **Infinity%**；
3. 预算透视把 0 当成「无效值」，而它是用户的明确选择。

## 决策

1. `/api/plan` 与 clone 的 budget 下限 **500 → 0**；只有负数/非整数/缺失/超上限 400。
2. 预算目标行移进 `baseLines`（生成与 refine **同源**），并按预算切换口径：
   - 穷游（预算 0 或**日均 <100 元**）：优先免费与低价项目（免费景点、公园、
     街区漫步、博物馆免费开放日、街头小吃、公共交通），不为凑预算加项目；
   - 正常预算：保持 80%-100% 区间约束不变。
3. 体检预算预警只在 `budget > 0` 时判定。
4. `budget.ts` 区分「穷游（0）」与「未设/无效」：前者给「只统计花费，不判达成」。
5. 表单不再预填 3000（预填 = 替用户做决定），改为空值 + 占位符口径 + 快捷档
   （穷游 0 / 1000 / 3000 / 8000）。

## 后果

- 「周末进城逛免费博物馆」这类需求不再被拒；
- 预算为 0 时预算透视只展示花费构成（诚实），不显示使用率；
- 日均 <100 元的判定阈值（`days * 100`）是经验值，后续可按实测调整。
