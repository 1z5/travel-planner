# ADR-009: 跨城/多城市行程（按天串段）

## 状态

已接受（2026-10-24，随 Phase「跨城」落地）

## 背景

用户需求原话：「我在深圳住，想去香港玩」。产品此前只有两种范围：

- `city`：单城市（POI 检索带 citylimit）；
- `region`：松散区域环线（川西环线、关西——高德不认识这个地名，必须关掉
  citylimit 否则检索被滤空）。

跨城是**第三种**东西：几座**具体**城市按天串段。它不能复用 region——关掉
citylimit 会让深圳的 POI 混进香港段；也不能复用 city——行程本来就在多座城。

## 决策

1. 新增 `PlanInput.cities: [{city, days}]`（2-4 座，有序），**days 之和必须等于
   由起止日期推导的总天数**（差一天就有一天没有城市，API 400）。
2. 每座城市**仍按 city 模式精确检索**（citylimit 按城开着），事实层逐城检索并
   **按城统计命中**——「深圳有覆盖、香港没有」要如实提示，不用全局命中数掩盖。
3. 体检（POI 验真/通勤）改用「当天所属城市」；`finalizePlan` 回填
   `plan.cities` 与 `PlanDay.city`，作为分享页/日历/工作台的单一事实来源。
4. prompt 给按天分段表 + 跨城日口径（上午收尾当前城市、下午前往下一城、抵达后
   只排轻松的点）。

## 跨境/城际通勤：不估算（本 ADR 最重要的部分）

高德**没有跨境路线**（不经过关口的驾车/公交），也不了解口岸排队、检录、签注。
因此：

- 服务端**不产生**任何城际/跨境通勤分钟数；
- 城际交通由用户以「重点活动（events）」形式按班次提供，作为时间锚点；
- prompt 明确「以用户提供的班次时间为准，没有就不要写具体分钟数」。

宁可让用户自己填班次，也不编一个看起来合理的通关时间——后者会直接害人误车。

## 后果

- 深港、广深、沪苏这类「居住地 + 目的地」场景可用；出境游（日韩欧美）仍受
  高德覆盖限制，会走「未核验」的诚实降级。
- 跨城日目前是粗粒度（上午收尾 + 下午抵达后排 1-2 个点）；按班次时间做
  「抵达前不排点」的硬约束是后续候选。
- `region` 与 `cities` 长期共存：前者是「一个区域内的环线」，后者是「几座城市
  的串段」。若未来统一，需要先解决 POI 检索口径的合并。
