# ADR-002: POI 查询三态原则

## 状态

已接受（2026-10）

## 背景

高德 POI 查询可能返回：命中 / 明确无结果 / 网络异常或 key 失效。早期实现把后两者都当「无结果」，导致 key 失效时把真实景点标成「未检索到」——预警系统自己变成谎言。

## 决策

POI 查询严格区分三态：

- **hit**：景点/餐厅真实存在
- **miss**：高德明确说没有 → 进 warnings「未在高德检索到」
- **error**：网络抖动 / key 失效 / QPS 超限 → 只汇总成一条系统提示，不进 warnings

## 理由

把「服务不可用」说成「景点不存在」是预警系统在撒谎，比没有推荐更糟。

## 后果

- error 态只汇总成 `plan.verification="partial"` 系统提示
- 该天通勤未知时跳过通勤/节奏判定，不用假数据污染指标
- 瞬时失败指数退避重试 3 次，非瞬时错误（key 无效）不重试
