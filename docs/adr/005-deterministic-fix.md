# ADR-005: 确定性修复 vs LLM 修复

## 状态

已接受（2026-10）

## 背景

行程体检发现问题后需要修复。有些问题可以用确定性算法修（时间轴顺延），有些需要 LLM 理解意图（换景点、改室内）。

## 决策

两类修复分开：

- **确定性**（/api/plan/adjust）：时间轴顺延，按真实路段时长重排，不调模型、不扣配额、毫秒级
- **LLM**（/api/plan/refine action:"fix"）：绕路/节奏/预算/天气/闭馆，服务端模板化指令让 AI 改一天

## 理由

确定性修复可预测、零成本、幂等。LLM 修复需要理解意图但慢且贵。分开后用户可以根据问题类型选择。

## 后果

- 时间轴「接不上」→ 一键顺延（adjust）
- 闭馆/绕路/节奏 → 一键修复（refine fix）
- 行程管家（copilot）给建议时也区分两类：retime → adjust，fix → refine
- LLM 修复用服务端模板化指令（客户端不能传 instruction），天然防注入
