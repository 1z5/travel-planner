# ADR-011: Trip Workspace 与产品/营销分域

## 状态

已接受（2026-10-24，Phase 0/1/2）

## 背景

用户反馈两轮，指向同一个结构问题：

1. 「本质是一个简单的页面一直往下平铺，太平庸」；
2. 「像公司官网，但我们想做的是供用户使用的产品」。

根因不是视觉，是**产品面与营销面没有分开**：根布局给所有路由挂同一套
SiteHeader/SiteFooter（营销导航 + 三栏信任页脚），首页是 hero + 表单 + 营销
区块，结果页/分享页/行中页都是「官网子页面」。同时行程本身是一页 6000px 的
长文档，没有视角切换，也没有直接操纵。

## 决策

1. **两个路由组**：`(app)` 用紧凑 AppShell（我的行程 / 新建），`(marketing)`
   只在 `/about` 挂营销壳；根布局只留 `<MotionPref>`。
2. **入口即产品**：`/` = 我的行程（localStorage 索引 + 空态），`/new` = 新建，
   `/w/[id]` = Trip Workspace，`/p` `/t` `/r` 保留为对外工件。
3. **一个行程对象，多个镜头**：Trip Header 常驻（城市/日期/核验状态/倒计时 +
   复制链接/分享页），镜头 = 规划 / 地图 / 调整 / 今日；出发当天自动落「今日」；
   `?view=` 深链直达某个镜头。
4. **直接操纵优先于对话**：「调整」镜头让用户自己排当天点位（拖拽/↑↓），服务端
   只做确定性重算（`/api/plan/adjust` 的 `op:"reorder"`，复用 `retimeDay`）；
   缺真实路段时不假装算得动——顺序照改、notes 说明原因。
5. 法务入口（隐私政策/用户协议）在产品壳底部常驻——ToC 产品面向公众，这是
   合规底线而不是营销装饰。

## 后果

- 产品从「生成器 + 文档」变成「工作台」；营销叙事集中到 `/about`，不再污染产品页。
- 「规划」镜头内容仍长（Phase 1 未重写 PlanView），后续候选：把逐天时间轴本身
  变成可拖拽画布、候选池（从地图/搜索加点进行程）、生成中可编辑骨架。
- 直接操纵只覆盖「天内重排」；跨天拖动、改时长、锁定必去点仍未实现。
