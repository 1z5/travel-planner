# 架构

应用由 Next.js App Router、领域模块和两种存储实现组成。开发可用进程内存，持久部署使用 PostgreSQL。模型服务和高德 API 由实例配置，Trip Check 的判定引擎可独立运行。

## 代码入口

| 路径                                   | 职责                                               |
| -------------------------------------- | -------------------------------------------------- |
| `app/(app)/`、`components/`            | 我的行程、新建、工作台、分享、今日、报告、行程体检 |
| `app/(marketing)/`                     | 关于、条款、城市模板、开放验真台                   |
| `app/api/`、`lib/server/`、`lib/auth/` | HTTP 边界、鉴权、请求校验、配额和事件              |
| `lib/plan/`、`lib/jobs/`               | 生成、计划编辑、校验、任务进度和版本               |
| `lib/trip/`、`app/api/journey/[id]/`   | 今日视图、执行记录、旅程报告                       |
| `lib/geo/`、`lib/prompts/`             | 地点、路径、地图、天气与模型提示                   |
| `lib/verify/`、`cli/`、`mcp/`          | 确定性核验、凭据、修复与调用入口                   |
| `lib/store/`、`prisma/`                | 内存和 PostgreSQL 存储、结构与迁移                 |

## 数据流

1. **本机行程**。`/local` 导入经过格式校验的行程文件，也能手动建行程。浏览器用 IndexedDB 按份保存计划和到达、跳过记录。编辑和「今日」读取同一份计划，记录按站点 ID 对应。用户准备离线时，Service Worker 缓存页面外壳和静态资源。普通导出用于传递计划，含进展的备份可在设备上恢复记录。
2. **生成**。表单提交 `POST /api/plan`，服务端校验与扣配额后返回任务 ID。后台先尝试查地点资料，再请求模型。长行程按「大纲 → 分日」并行生成，按天序发布进度。本机模式把结果返回给浏览器保存。启用持久分享时，结果体检后通过 `commitPlan()` 存储并返回分享 ID。
3. **在线行中**。`resolvePlan()` 提供分享、工作台、今日、报告和日历的共用读入口。站点 ID 随计划调序沿用。登录的行程主人可以独立提交到达或跳过记录，接口按站点 ID、命令 ID 和计划版本做校验。计划和执行记录通过各自的读写路径流转。
4. **核验**。文本抽取可调用模型，用户确认结构化输入后，由 `lib/verify/` 生成结构和事实覆盖两个结论。确定性修复和凭据复算共用规则引擎。公开核验只依据输入文档及声明的来源，两轴均不代表实时查店。
5. **读取与分享**。读取优先查已存的计划，随后查内置样本，最后按配置尝试旧任务链接。普通分享链接包含访问能力，持有者可查看，并可针对可编辑行程修改计划。私人行中记录另查登录和所有者。改动需保留这两套权限的区别。

本机入口使用完整文档导航进入 `/local`，Service Worker 依据来源文档的路径接受离线准备请求。`?open=tokyo` 在内存打开当日示例，首次记录或编辑时保存副本；`?open=recent` 读取最近更新的文件。站点方位图在客户端按已有坐标投影，每次主动定位计算的距离只驻留在当前页面。

备份的可选 `notes` 字段保存旅行手记，包含记录时间、正文、可选地点和一张可选的 JPEG 预览。浏览器在选图后重新编码，长边至多 960 像素，单张至多 96 KiB。普通计划和至多 2 MiB 的备份仍用 v1，较大的私人备份使用 v2，上限为 32 MiB。日常保存无需生成备份。地点名称保留写下时的文字，编辑计划后仍可回看。到达打卡将当时的地点名称和时间写入备份的可选 `arrivals` 字段；未附时间的旧记录在回看时单列。旧版文件可直接导入，普通计划导出省略手记、照片和打卡。含手记的备份应使用支持手记的版本恢复。

`?open=walk` 建立随走草稿，首次记录时写入本机行程库。可选的 `walk: true` 在重开或导入时直接进入手记。计划外停留使用独立的记录 ID 写入 `arrivals`，无需插入计划。用户可为每一站单独附上浏览器返回的经纬度和精度，方位图用本地投影显示定位点，私人备份包含这些点。位置采集只有一次性请求。

本机库 `tp-local-trips` 分开存行程正文、列表摘要和按条索引的照片。首页只查询摘要，手记照片接近可视区时从照片库读取，完整备份在同一只读事务内取回正文和照片。保存与移除在读写事务内比对当前记录版本。同一版本的两个标签页先提交的一方生效，另一方保留正在编辑的输入。

首次打开新库时，旧 `tp.local-trip-files.v1` 在数据库升级事务中一次迁移。旧地址保留，缺失 ID 的行程补发 ID，原有排序保留。无法读取的条目单列数量，原始存档留在 `localStorage`。若迁移事务中断，下次打开会重试。备份保留私人进展和标题，不携带本机 ID。要回退到旧版应用，可用原始存档找回迁移前的数据，新写入的记录需要先在新版导出。

`/local` 在已有当前版本缓存时最多等待网络 1.2 秒。存储升级时只回退到兼容的页面外壳。对已经准备过的设备，联网打开后会自动尝试更新，失败时显示重试入口。草稿保存在独立的 IndexedDB 记录中，首次保存行程时转入新 ID，正式保存手记时在同一事务内清理。

## 存储与部署

本机行程的城市包位于 `lib/geo/city-packs/`。东京和巴黎包按站点存地图检索词、地点出处及可用的开放时间资料。编辑时选站会把资料写入行程文件，「今日」统计当天站点附带资料的数量。场所及区政府页面提供人工整理的资料来源。本机日历导出按声明的目的地时区转换，夏令时边界存在歧义时保存全天事件，并在说明中保留当地时段。

本机体检通过 `lib/verify/local-plan.ts` 生成 Trip Check 文档。地点按城市、名称和地图检索词匹配内置城市包，开放时间使用行程当天所在月份的记录。结构判定复用同一套规则引擎，文件自带的坐标和估算路段留在计划视图中供参考。

`Plan` 存计划和输入，`Job` 存生成任务，`JourneyMark` 存行中记录，`QuotaBucket`、`SmsCode`、`TripEvent` 分别处理限流、验证码和产品事件。PostgreSQL 行程没有自动过期时间。行程删除与分享撤销尚无产品入口。部署前核对 [部署指南](DEPLOY.md) 和 [迁移文件](../prisma/migrations/)。

浏览器端索引、愿望清单、档案设置和部分离线体验依赖站点存储。档案选填后可随行程请求提交。清除设备数据只影响本机状态。

## 验收与已知边界

- `npm run gate` 运行类型、lint、格式、单测和端到端测试。端到端测试用本地桩服务注入地图、模型及登录故障。CI 另有生产构建、覆盖率和 PostgreSQL 测试。
- 进程重启会中断生成任务。多实例之间的并发上限与运行中队列尚未统一。
- POI 三态区分命中、查无结果和服务错误。营业时间缺失或路线估算失败时应显示未知或降级结果。
- 样式叠加约定见[前端设计](design/ATLAS-V6.md)，安全与兼容性见 [ADR](adr/) 和[接口文档](API.md)。
